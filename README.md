# Big Bubble — онлайн-каталог и конструктор

Адаптивный Next.js 16 / React 19 / TypeScript сайт по визуальному референсу `big-bubble-interface-v2-reference.png`.

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

Для проверки production-сборки: `npm run build && npm run start`.

## Покупательский путь

- `/` — витрина, категории, подборка, вход в конструктор.
- `/catalog` и `/catalog/[slug]` — поиск, фильтры, сортировка, карточки товара.
- `/constructor` — редактор набора: отдельные элементы и весь каталог сайта (включая арки, оформление и подарки) берутся из общего списка товаров. Есть сцена с перетаскиванием, настройкой размера и поворота, готовые шаблоны, сохранение черновика в браузере и живая примерная цена. На телефоне товар можно добавить нажатием и затем переместить на сцене. Полный реальный ассортимент Big Bubble нужно будет импортировать в общий каталог по утверждённому прайсу; новые товары автоматически появятся в конструкторе.
- `/favorites`, `/cart` — избранное и корзина; состав конструктора сохраняется вместе с товаром.
- `/checkout` — создание заказа, выбор доставки и оплата внутри сайта.
- `/delivery`, `/contacts` — условия покупки и связь.

Корзина хранится в браузере. Сервер независимо валидирует каждую позицию и пересчитывает цену набора, затем фиксирует заказ в `data/paid-orders/`. Заказы проходят состояния `pending_payment`, `paid_demo` или `paid`. Клиентский ответ платёжного виджета не меняет статус заказа: в боевом режиме это делает только проверенный Pay webhook.

## Оплата

Локально включён `PAYMENT_MODE=demo`: покупатель проходит checkout и подтверждает **имитацию** оплаты. Никаких банковских данных форма не запрашивает и деньги не списывает. Примерные цены и тариф доставки используются только для демонстрации.

Для подключения CloudPayments Kazakhstan нужны утверждённый прайс, тариф доставки, мерчант-аккаунт и HTTPS-домен. В `.env.local` задайте `PAYMENT_MODE=cloudpayments`, `PAYMENTS_LIVE_ENABLED=true`, `PRICES_APPROVED=true`, `CLOUDPAYMENTS_TERMINAL_ID`, `CLOUDPAYMENTS_API_SECRET` и `DELIVERY_FEE_KZT`. Не храните секрет в клиентском коде. В кабинете эквайринга включите Check webhook на `/api/payments/cloudpayments/check` и Pay webhook на `/api/payments/cloudpayments/pay`. Виджет загружается с официального домена CloudPayments и не передаёт карточные реквизиты серверу Big Bubble.

JSON-файлы пригодны для локального прототипа. Для публичного сайта нужна постоянная база данных и административный интерфейс обработки оплаченных заказов. Товарные цены, составы, доставка и права на фото должны быть утверждены Big Bubble до реальных списаний.
