# Big Bubble — онлайн-каталог и конструктор

Адаптивный Next.js 16 / React 19 / TypeScript сайт по визуальному референсу `big-bubble-interface-v2-reference.png`.

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

Для проверки production-сборки: `npm run build && npm run start`.

## Покупательский путь

- `/` — витрина, категории, подборка, вход в конструктор.
- `/catalog` и `/catalog/[slug]` — поиск, фильтры, сортировка, карточки товара.
- `/constructor` — два режима. Готовые композиции сохраняют исходное расположение; рядом можно добавить подарки и фольгированные фигуры. Для своей арки можно выбрать высоту 1, 1,5 или 2 м, схему X/градиент/спираль/случайную/чередование и установить шар в каждый круглый слот. Шары автоматически заполняют соответствующие позиции. Пустой слот оставляет видимые пробелы. Каждый шар можно отдельно перекрасить, изменить его размер и материал, поменять местами с другим шаром. Черновик сохраняется в браузере.
- `/favorites`, `/cart` — избранное и корзина; состав конструктора сохраняется вместе с товаром.
- `/checkout` — создание заказа, выбор доставки и оплата внутри сайта.
- `/delivery`, `/contacts` — условия покупки и связь.

Корзина хранится в браузере. Сервер независимо валидирует каждую позицию и пересчитывает цену набора, затем фиксирует заказ в `data/paid-orders/`. Заказ арки содержит высоту, схему, слоты и параметры каждого изменённого шара. К сумме товаров добавляется 10% за сборку, установку и упаковку всей корзины; доставка включена. Заказы проходят состояния `pending_payment`, `paid_demo` или `paid`. Клиентский ответ платёжного виджета не меняет статус заказа: в боевом режиме это делает только проверенный Pay webhook.

Вместимость и стоимость каркаса в `lib/arch.ts` пока ориентировочные: 1 м — 24 шара и 9 000 ₸, 1,5 м — 30 шаров и 13 500 ₸, 2 м — 36 шаров и 18 000 ₸. Количество, размеры и цены необходимо сверить с мастерской до приёма реальных платежей. Каталог содержит демонстрационный ассортимент; реальные товары и прайс нужно загрузить отдельно.

## Оплата

Локально включён `PAYMENT_MODE=demo`: покупатель проходит checkout и подтверждает **имитацию** оплаты. Никаких банковских данных форма не запрашивает и деньги не списывает. Примерные цены используются только для демонстрации.

Для подключения CloudPayments Kazakhstan нужны утверждённый прайс, подтверждённые параметры арок, мерчант-аккаунт и HTTPS-домен. В `.env.local` задайте `PAYMENT_MODE=cloudpayments`, `PAYMENTS_LIVE_ENABLED=true`, `PRICES_APPROVED=true`, `CLOUDPAYMENTS_TERMINAL_ID` и `CLOUDPAYMENTS_API_SECRET`. Не храните секрет в клиентском коде. В кабинете эквайринга включите Check webhook на `/api/payments/cloudpayments/check` и Pay webhook на `/api/payments/cloudpayments/pay`. Виджет загружается с официального домена CloudPayments и не передаёт карточные реквизиты серверу Big Bubble.

JSON-файлы пригодны для локального прототипа. Для публичного сайта нужна постоянная база данных и административный интерфейс обработки оплаченных заказов. Товарные цены, составы, доставка и права на фото должны быть утверждены Big Bubble до реальных списаний.
